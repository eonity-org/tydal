# TYDAL Bulk Folder Uploader

Reads files from a local folder and uploads them to TYDAL via the REST API.

For each file the script will:
1. Create a resource (name inferred from filename)
2. Upload the file
3. Trigger AITY enrichment (text extraction + AI analysis)
4. Wait for the AI to finish
5. **Auto-accept** the AI-suggested **name** and **description**
6. **Skip** AI tag suggestions — these require manual review in the UI

Progress is saved in `.tydal_upload_state.json` inside the folder so the script
can be re-run safely; completed files are skipped.

## Setup

```bash
cd tydal/tools/bulk_uploader

# Create an isolated virtual environment (required on macOS with Homebrew Python)
python3 -m venv .venv
source .venv/bin/activate

pip install -r requirements.txt
```

Re-activate the venv each time you open a new terminal before running the script:

```bash
source tydal/tools/bulk_uploader/.venv/bin/activate
```

## Usage

### Single-pass mode (default)

Upload files one by one, waiting for AITY analysis before moving to the next:

```bash
python upload.py /path/to/your/files \
  --email admin@example.com \
  --password secret \
  --org-id <organization-uuid> \
  --collection-id 3
```

### Two-phase bulk mode

Upload everything fast (AITY runs in the background on the server), then accept suggestions later:

```bash
# Phase 1 — upload all files without waiting
python upload.py /path/to/your/files \
  --phase upload \
  --email admin@example.com --password secret \
  --org-id <uuid> --collection-id 3

# Phase 2 — collect AI results and apply name/description (run after a few minutes)
python upload.py /path/to/your/files \
  --phase accept \
  --email admin@example.com --password secret \
  --org-id <uuid>
```

Note that `--collection-id` is not needed for `--phase accept`.

### All options

| Flag | Default | Description |
|------|---------|-------------|
| `folder` | (required) | Local folder containing files |
| `--phase` | `full` | `full`, `upload`, or `accept` |
| `--api-url` | `http://localhost:8000/api/v1` | TYDAL API base URL |
| `--email` | (required) | TYDAL login email |
| `--password` | (required) | TYDAL login password |
| `--org-id` | (required) | Organization UUID |
| `--collection-id` | (required for full/upload) | Target collection integer ID |
| `--visibility` | `organization` | `private`, `organization`, `workspace`, `public`, `draft` |
| `--extensions` | all files | Comma-separated list, e.g. `pdf,jpg,png` |
| `--poll-timeout` | `600` | Max seconds to wait for AITY per file |
| `--state-file` | `<folder>/.tydal_upload_state.json` | Custom state file path |

### Examples

```bash
# PDFs and images only, production server, single-pass
python upload.py ~/assets \
  --api-url https://api.tydal.com/api/v1 \
  --email admin@example.com --password secret \
  --org-id 018f1234-abcd-7000-8000-000000000001 \
  --collection-id 5 \
  --extensions pdf,jpg,jpeg,png,webp

# Re-run any phase safely — completed files are always skipped
python upload.py ~/assets --phase accept --email ... --org-id ...
```

## Finding your Org ID and Collection ID

- **Org ID**: shown in the admin panel URL or via `GET /api/v1/organizations`
- **Collection ID**: integer ID from `GET /api/v1/workspaces` or the admin UI

## Tags

Tag suggestions generated by AITY are intentionally **not** auto-accepted.
Open the resource in the TYDAL UI to review and apply tags manually.

## State file

The state file (`.tydal_upload_state.json`) records each file's outcome:

```json
{
  "report.pdf": {
    "status": "done",
    "resource_id": "018f1234-...",
    "accepted_name": "Q3 Financial Report",
    "accepted_description": "Quarterly financial results...",
    "done_at": "2026-05-14T10:30:00Z"
  }
}
```

Delete the state file (or a specific entry) to re-upload a file.
